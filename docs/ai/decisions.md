## 2026-11-06 — Прозрачность — цветами темы, `MagicNumber` не проверяет `theme/`
- **Статус:** принято, [#11](https://github.com/efimov-r/aisdme/issues/11)
- **Контекст:** в UI было 6 вызовов `copy(alpha = …)` у цветов темы; вид зависел от фона под элементом, а цвета не все лежали в теме. Новые hex-цвета в `AisDmeColors` роняли detekt (`MagicNumber`), старые были в baseline
- **Решение:** у каждой прозрачной версии — свой цвет в `AisDmeColors` в обеих темах: `menuSelected`, `textSecondary`, `menuDivider` — непрозрачные, смешаны с `surface`; `hoverButton` — с альфой в hex, кнопки стоят на разном фоне; цель drag & drop в дереве — общий `dropTargetElement`. В `detekt.yml` `MagicNumber` исключает `**/theme/**` (решение пользователя)
- **Почему:** все цвета — в одном месте, по имени; по образцу `selectAndFocus` и `dropTargetElement`. Hex-литерал в теме и есть смысловая константа — имя поля, а Kover `theme/` уже не считает
- **Альтернативы:** `const val` на каждый цвет — по два имени на цвет; дописать ID в baseline руками — то же пересоздание baseline

## 2026-11-06 — Шина событий: без replay и без потерь
- **Статус:** принято, [#27](https://github.com/efimov-r/aisdme/issues/27)
- **Контекст:** `replay = 1` отдавал позднему подписчику старое событие; `extraBufferCapacity = 64` + `DROP_OLDEST` + `tryEmit` молча теряли события при переполнении
- **Решение:** `replay = 0`, `extraBufferCapacity = Int.MAX_VALUE`; подписка — `AppEventBus.subscribe` с `UNDISPATCHED`: подписан до возврата, события сразу после него не теряются
- **Почему:** события редкие (действия пользователя, пакеты watcher), неограниченный буфер не страшен; `publish` остаётся обычной функцией — её вызывают из обработчиков кликов
- **Альтернативы:** `SUSPEND` + `emit` — `publish` пришлось бы сделать `suspend` во всех местах вызова

## 2026-11-06 — Состояние вида дерева — в `ProjectTreeState`, состояние просмотрщика — во вкладке
- **Статус:** принято, [#27](https://github.com/efimov-r/aisdme/issues/27)
- **Контекст:** `ProjectNode` хранил выделение, пометку «вырезан» и позицию на экране; `TabCashFileImg` — масштаб и сдвиг изображения
- **Решение:** выделение (`TreeSelection`), вырезанные и позиции для меню — в `ProjectTreeState`, по файлам. `ImageViewerState` остаётся во вкладке
- **Почему:** узлы пересоздаются при чтении диска, а состояние по файлу переживает это; вырезание нескольких узлов — список корней, без рекурсивной разметки. Масштаб и сдвиг — состояние конкретной вкладки (как состояние редактора в IntelliJ), при переключении вкладок должны сохраняться
- **Альтернативы:** `ImageViewerState` в composable — терялся бы при переключении вкладок; `expanded` тоже вынести из `DirNode` — он связан с ленивой загрузкой и конфигом, оставлен в узле

## 2026-11-05 — Ленивая загрузка дерева проекта
- **Статус:** принято, [#28](https://github.com/efimov-r/aisdme/issues/28)
- **Контекст:** дерево читало с диска все папки проекта, включая `.git` и `build`; на Linux `WatchService` регистрировал каждую папку (лимит inotify, время открытия)
- **Решение:** свёрнутая папка не читается, пока её не раскроют (`DirNode.loaded`). На Linux watcher следит только за прочитанными папками; на Windows по-прежнему один ключ на корень с `FILE_TREE`. Связь дерева и watcher — прямой вызов из `AppController`, не шина: шина при переполнении теряла события молча (исправлено в [#27](https://github.com/efimov-r/aisdme/issues/27), прямая связь оставлена)
- **Почему:** как в IntelliJ IDEA; размер проекта почти не влияет на открытие, обход выделенных узлов идёт только по прочитанным папкам
- **Альтернативы:** скрыть служебные папки — большие пользовательские папки всё равно читались бы целиком, а в `build` лежит вывод сборки

## 2026-11-05 — Quality gates: detekt + Kover в `check`
- **Статус:** принято, [#19](https://github.com/efimov-r/aisdme/issues/19)
- **Контекст:** нужны линтер, статический анализ и порог покрытия в CI. Опора — список [dev-quality-gates](https://github.com/mokevnin/dev-quality-gates) (CC0): для Kotlin в нём рекомендован только detekt, ktlint — «Under review»
- **Решение:** detekt 1.23.8 (задача `detekt`, без type resolution) и Kover 0.9.11 входят в `check`, CI запускает `gradlew build`. `detekt.yml` поправлен только там, где стандарт противоречит `style.md`: имена `@Composable`, `rootPackage`, перевод строки в конце файла, ранние `return`, магические числа в `@Composable`, wildcard-импорты. Старый код: сначала прогон без baseline, исправлено очевидное (мёртвый код, пустые блоки), остальное (120) — в baseline; найденные баги — в #26. Порог покрытия — текущее значение (1%), поднимается с #15–17
- **Почему:** гейт через Gradle — одна команда для разработчика, агента и CI, без отдельных инструментов
- **Альтернативы:** форматтер (Spotless + ktlint) — переписал бы код под чужой стиль; mise + hk (хуки) — версии и так закреплены Gradle, гейт — CI; detekt 2.0 — alpha и нужен Gradle 8.14.3+; общие проверки (Betterleaks, jactionlint, Dependabot, diff-cover, typos) — решили не добавлять

## 2026-11-05 — CI без `gradle/actions/setup-gradle`
- **Статус:** принято, [#18](https://github.com/efimov-r/aisdme/issues/18)
- **Контекст:** нужен CI на GitHub Actions с кэшем Gradle. В `gradle/actions` v6 кэширование вынесено в проприетарный компонент `gradle-actions-caching`: используя его, принимаешь отдельные Terms of Use Gradle
- **Решение:** кэш — `actions/setup-java` с `cache: gradle`; проверка wrapper-jar — отдельный шаг `gradle/actions/wrapper-validation` (кэш не использует); запуск — `./gradlew build` в `bash` на обеих ОС
- **Почему:** всё под MIT, без чужих условий использования; кэша зависимостей для одного модуля хватает
- **Альтернативы:** `setup-gradle` v6 — условия использования; `setup-gradle` v5 — старая версия, обновляться всё равно придётся

## 2026-11-05 — Тесты на JUnit 5 + `kotlin.test`
- **Статус:** принято, [#14](https://github.com/efimov-r/aisdme/issues/14)
- **Контекст:** тестов не было, перед #15–17 нужен тестовый фреймворк
- **Решение:** `testImplementation(kotlin("test"))` — Kotlin-плагин сам подключает `kotlin-test-junit5`; `junit-platform-launcher` объявлен явно, иначе Gradle 8 предупреждает о его автозагрузке; `useJUnitPlatform()`
- **Почему:** знаком по другим проектам, без отдельного Gradle-плагина, IDEA запускает из коробки
- **Альтернативы:** Kotest — свой DSL и плагин, для учебного проекта лишняя сложность

## 2026-11-05 — Всё платформенное — в пакете `platform/`
- **Статус:** принято, [#12](https://github.com/efimov-r/aisdme/issues/12)
- **Контекст:** `os.name` проверялся в нескольких местах по-разному (`contains("win")`, `== "linux"`), ветки для Windows не проверялись
- **Решение:** интерфейс `IPlatform`, реализации `WindowsPlatform` и `LinuxPlatform`, выбор — `Platform.current`. Классы вне `platform/` от ОС не зависят и `os.name` не читают
- **Почему:** платформенный код в одном месте, ОС определяется один раз; новая ОС — один новый класс; в тестах можно подставить реализацию другой ОС
- **Альтернативы:** один `object` с `when (os)` в каждой функции — смешал бы конфиги, буфер обмена и файловый менеджер; передача через `AppControllerBuilder` — `ConfigPaths` нужен раньше, чем собраны контроллеры

## 2026-11-05 — Выбор проекта при старте через `JFileChooser`
- **Статус:** принято, оформление — [#21](https://github.com/efimov-r/aisdme/issues/21)
- **Контекст:** без последнего проекта приложение падало ([#2](https://github.com/efimov-r/aisdme/issues/2))
- **Решение:** `JFileChooser` с `DIRECTORIES_ONLY`, системный look & feel — только на время создания диалога (`ui/win/ProjectChooserHelper.kt`). Отмена закрывает приложение

- **Альтернативы:** `java.awt.FileDialog` — на Windows не выбирает папки; нативные диалоги (LWJGL `tinyfd`, `nfd`) — нативная библиотека на каждую ОС; проект по умолчанию — скрытое поведение

## 2026-11-05 — Настройки IDE из `.idea/` не коммитятся
- **Статус:** принято
- **Контекст:** IntelliJ создала `.idea/gradle.xml`, `misc.xml`, `kotlinc.xml`, `vcs.xml`
- **Решение:** добавить их в `.gitignore`. Источник правды — Gradle; IDE создаёт эти файлы заново при импорте проекта
- **Почему:** в `gradle.xml` и `misc.xml` записаны имена JDK конкретной машины (`temurin-24`, `17`), а на Linux и Windows они разные: файлы менялись бы туда-обратно
- **Альтернативы:** коммитить, как советует JetBrains для общих настроек, — для одного разработчика на двух ОС пользы нет, только шум в diff

## 2026-03-12 — Piece Table + LineIndex + Undo
- **Статус:** принято, не реализовано
- **Контекст:** нужно открывать и быстро редактировать большие файлы, вставлять в середину и отменять ввод
- **Решение:** текст хранить в Piece Table, позиции строк — в LineIndex, историю — в UndoManager с объединением посимвольных правок. План — [todo.md](todo.md)
- **Почему:** `TextFieldValue` хранит весь текст одной строкой и копирует его при каждом изменении; поиск строки перебором — O(n)
- **Альтернативы:** undo через `TextFieldValue`, как было в первом плане, — отказались по тем же причинам
