# Стиль

Договорённости о стиле кода и текстов в этом проекте. Они важнее общих привычек агента. Цель — новый код визуально не отличается от существующего.

## Код (Kotlin)

### Форматирование

- Отступ — 4 пробела, без табов. Продолжение выражения (цепочки, аргументы) — ещё +4.
- Переводы строк — LF. Последняя строка файла — без перевода строки.
- Длина строки — обычно до ~120 символов, жёсткого предела нет.
- Скобки — K&R: `{` в конце строки, `} else {` на одной строке.
- Пробелы: по умолчанию `if (`, но `if(` в коротких проверках тоже норма; лямбда `{ x ->`, слитно `{ x->` тоже встречается; тип возврата `fun x(): T`, у многострочных параметров часто `) : T {`.
- Однострочные проверки без скобок: `if (x == null) return`, `?: return`.
- Многострочные параметры и аргументы — каждый на своей строке, закрывающая `)` — на отдельной. В вызовах — именованные аргументы и запятая после последнего аргумента (trailing comma).
- Цепочки `Modifier` — каждый вызов с новой строки, отступ +4. Короткие цепочки можно в одну строку: `Modifier.fillMaxSize().panel()`.

### Пустые строки

- Между функциями — одна пустая строка.
- Внутри функции пустой строкой отделяются логические шаги.
- Группы полей отделяются пустой строкой.

### Комментарии

- Только там, где без них непонятно. Много комментариев не писать.
- На русском, короткие, в конце строки с кодом: `//открыть новый проект`. Строк, где только комментарий, избегать. Пробел после `//` обычно есть, но не обязателен.
- KDoc почти не пишется; если нужен — короткий `/** ... */` над функцией.
- Старый код удалять, а не закомментировать: история есть в git.

### Имена

- Классы и объекты — PascalCase, функции и переменные — camelCase, константы — `private const val UPPER_SNAKE` в начале `object`.
- Транслит и русские корни допустимы. Существующие имена с опечатками (`contexmenu`, `TabCash`, `Dragailable`, `Proporcial`, `tolltipState`) не исправлять без просьбы — новые имена брать по образцу соседних файлов.
- Префикс `_` у приватных backing-полей: `_textFieldValue` / `textFieldValue`, `_globalMess` / `globalMess`.
- Суффиксы ролей: `*Controller` — состояние и логика части приложения; `*State` — состояние UI; `*Helper` — утилиты; `*Dialog` — диалог; `I*` — интерфейс (`IFileController`).
- Короткие имена в лямбдах: `it`, `s`, `l`; результат функции — `res`.

### Файлы и пакеты

- Один класс на файл, имя файла = имя класса. Мелкие связанные типы (`sealed interface`, `data class`) — в том же файле.
- `package` брать у соседних файлов той же папки: он не всегда совпадает с папкой ([gotchas.md](gotchas.md)).

### Идиомы

- Асинхронность — корутины: `CoroutineScope` контроллера, `Mutex().withLock`, `withContext(Dispatchers.IO)`, возврат в UI — `Dispatchers.Swing`.
- Null: `?.let { }`, `?: return`, `?: run { ...; return }`; `!!` допустим.
- Явные метки возврата: `return@launch`.
- Функции-выражения: `fun deleteSelected() = filesController.delete(...)`.
- Ошибки: `runCatching { }` или `try { } catch (e: Exception) { Log.e(...) }`.
- Логирование — свой `utils/Log`: `Log.d(...)`, `Log.e(...)`; сообщения короткие, на русском или английском.
- Compose: состояние — `mutableStateOf` / `mutableStateListOf` в контроллерах, доступ — через `LocalAppController.current`, `val x by remember { mutableStateOf(...) }`, цвета — только через `LocalAisDmeColors.current`, отступы — `AisDmeSpacing`, формы — `AisDmeShapes`.
- Глобальное состояние — `object` (`GlobalConfig`), без DI-фреймворка.

### Тесты

- JUnit 5 + `kotlin.test`: `@Test`, `assertEquals`, `assertNull` и др. — из `kotlin.test`, не из `org.junit`.
- Класс — `<Класс>Test`, в той же папке и том же `package`, что тестируемый класс, но в `src/test/kotlin/`.
- Имя теста — на английском, camelCase, что проверяется и что ожидается: `blankNameReturnsError`.
- Перед каждым тестом — строка комментария на русском: что проверяет тест (исключение из правила «комментарий в конце строки»).
- Тест, результат которого зависит от ОС (пути, буфер обмена, файловый менеджер, всё из `platform/`), — всегда в паре: такой же тест для каждой платформы (`WindowsPlatform` и `LinuxPlatform`). Тест без зависимости от ОС — один на все платформы.

## Тексты

- Сообщения коммитов — на русском, коротко, со строчной буквы, без точки в конце: `горизонтальный скролл редактора`, `фиксы самообновления дерева`.
- Тексты интерфейса и логов — на русском или английском, как в соседнем коде.
