# Пульт отладки: как работать

Инструкция агенту: как запускать приложение, смотреть окно и нажимать кнопки. Устройство пульта — [architecture.md](architecture.md), «Пульт отладки».

## Цикл

1. Код менял — сначала `.\gradlew.bat build` (гейт). Приложение при этом должно быть закрыто.
2. Запустить в фоне (`run_in_background`): `.\gradlew.bat run -PdebugCtl`. Не ждать и не опрашивать лог.
3. Сразу слать команды: `.\scripts\debug-ctl.ps1 "команда 1" "команда 2"`. Скрипт сам ждёт сборку и старт (до 180 с), печатает ответ по строке на команду. Каждая команда — отдельный аргумент в кавычках.
4. Скриншот смотреть через Read: `build/debug-ctl/<имя>.png` (путь печатает `shot`).
5. В конце — команда `close` (штатное закрытие, состояние сохраняется). Не `Stop-Process`.

Коды выхода скрипта: 0 — ок, 1 — какая-то команда вернула `error` (остальные после неё не выполнялись), 2 — нет команд, 3 — приложение не запущено или завершилось, 4 — нет ответа за 180 с.

## Без ручных апрувов

В `.claude/settings.json` разрешены точные формы: `.\gradlew.bat build | test | detekt | koverLog | run -PdebugCtl` и `.\scripts\debug-ctl.ps1 *`. Всё остальное — апрув, поэтому:

- одна простая команда на вызов: без `cd`, `-p`, абсолютных путей, `$env:`, `&`, `;`, `|`, `2>&1`;
- не придумывать новые формы (`gradlew run` без `-PdebugCtl`, лишние флаги, `Stop-Process`) — они потребуют апрув;
- файлы читать только Read, по относительному пути внутри проекта;
- `curl` не нужен: сети у пульта нет.

## Команды

Координаты — пиксели скриншота (окно в dip = пиксели / `scale` из ответа `shot`, обычно 1.25). События синтетические: настоящая мышь не двигается, окно может быть под другими, работать параллельно можно.

| Команда | Что делает |
|---|---|
| `state` | текст: тема, дерево (раскрыто `[-]`, свёрнуто `[+]`, выделено `*`, точка клика `@x,y`), вкладки левой и правой половины (`*` — активная, в скобках статус записи) |
| `text [left\|right]` | полный текст активной вкладки половины |
| `shot [имя] [x y ширина высота]` | PNG окна; с четырьмя числами — вырезка области (для деталей) |
| `node [right] [double] имя` | клик по узлу дерева; имя как в `state`, для одинаковых — путь от корня: `fold/a.txt` |
| `arrow имя` | раскрыть или свернуть папку |
| `click x y [left\|right\|middle] [число]` | клик по координатам |
| `move x y`, `drag x1 y1 x2 y2`, `scroll x y шаги` | мышь; `scroll` > 0 — вниз |
| `type текст` | ввод символов (кириллица тоже) |
| `key ctrl+shift+s` | сочетание: `ctrl`, `shift`, `alt`, `meta` + клавиша (`enter`, `esc`, `backspace`, `delete`, `down`, `f6`, `a`…) |
| `wait мс` | пауза |
| `dump` | дерево компонентов AWT (отладка самого пульта) |
| `close` | закрыть окно |

## Приёмы

- Сначала `state` (дёшево и точно), скриншот — для вёрстки, цветов, меню, диалогов, плашек: их в `state` нет.
- Позиции есть только у видимых узлов дерева. Нужный узел скрыт — `arrow` на папке, потом `node`.
- Двойной клик открывает файл. Вкладка в debug 300 мс в статусе `load` — перед `state` поставить `wait 500`.
- Автосохранение через 2 с: набранное попадает в файл. Откатывать ввод `key backspace` нужное число раз; `shift+home` + `delete` стирает всю строку (так уже потеряли строку тестового файла).
- Клик по пустому месту под текстом фокус редактору не даёт: кликать по самому тексту.
- Контекстное меню, диалоги и плашки рисуются внутри окна и видны на снимке; меню закрывает `key esc`. Системные окна (`JFileChooser`) на снимок не попадают.
- Команды ждут, пока загрузится конфиг проекта, белого снимка нет. Но сразу после старта вкладки ещё `load` (на снимке «Load …»): первой командой ставить `wait 500`.

## Осторожно

- Приложение открывает последний проект из глобального конфига. Перед кликами по дереву смотреть корень в `state`. Удаление, перенос, вставка, переименование — только в тестовом проекте `testprojforaisdme`; открыт другой — `close` и сказать пользователю.
- Диалог с подтверждением (Delete, Rename) без нужды не доводить до OK.
- Остановленное ошибкой приложение (скрипт вернул 3) — причина в выводе фоновой задачи `run`; читать её, только если это нужно.

## Не проверено

- `drag` (перетаскивание в дереве меняет файлы, на тестовом проекте не гонял).
- Linux: скрипт только для Windows. Руками: записать `build/debug-ctl/<id>.tmp`, переименовать в `<id>.cmd`, читать `<id>.out`.
