# Пульт отладки: как работать

Инструкция агенту: как запускать приложение, смотреть окно и нажимать кнопки. Устройство пульта — [architecture.md](architecture.md), «Пульт отладки».

## Песочница

`.\gradlew.bat run -PdebugCtl` каждый раз пересоздаёт тестовый проект `build/debug-fixture/proj` и свой глобальный конфиг `build/debug-ctl/config`. Данные пользователя и его настоящий конфиг не трогаются, портить и ломать можно свободно: следующий запуск начнётся со свежих файлов.

Проект: `main.asm`, `notes.txt`, `a.txt`, `тест.txt`, `pic.png`, папки `fold/` (`a.txt`, `folda/Текстовый документ.txt`, пустая `foldb/`) и `fold2/` (`b.txt`). Вкладок нет, дерево свёрнуто.

## Цикл

1. Код менял — `.\gradlew.bat build` (гейт). Приложение при этом закрыто. Для проверки одной правки отдельный `build` не нужен: `run` сам компилирует.
2. Запустить в фоне (`run_in_background`): `.\gradlew.bat run -PdebugCtl`. Не ждать и не опрашивать лог.
3. Сразу слать команды: `.\scripts\debug-ctl.ps1 "команда 1" "команда 2"`. Скрипт сам ждёт сборку и старт (до 180 с), печатает ответ по строке на команду. Каждая команда — отдельный аргумент в кавычках. `@путь\файл.txt` — команды из файла.
4. Скриншот смотреть через Read: `build/debug-ctl/<имя>.png` (путь печатает `shot`).
5. В конце — `close` (штатное закрытие). Не `Stop-Process`.

Коды выхода `debug-ctl.ps1`: 0 — ок, 1 — команда вернула `error` (остальные после неё не выполнялись), 2 — нет команд, 3 — приложение не запущено или завершилось, 4 — нет ответа за 180 с.

## Сценарии

`scripts/scenarios/*.txt` — проверки на свежем приложении: команды пульта, строки с `#` — комментарии. Основные: `theme`, `rename-dialog`, `open-and-edit`, `tabs`, `tree-arrows`, `external-change`, `external-delete`, `dnd-move`, `dnd-editor`, `dnd-empty-editor`, `splitters`, `tabs-scroll-to-active`, `tabs-scroll-on-activate`, `bottom-panel-narrow`, `bottom-panel-halves`, `uncaught-error`. Сценарий на найденный, но не починенный баг класть в `known-bugs/`: по умолчанию он не запускается, по имени запускается и падает; после починки перенести в основные. Запуск: `.\scripts\debug-scenario.ps1` (основные) или `.\scripts\debug-scenario.ps1 theme tabs` (названные, в том числе из `known-bugs`). Раннер сам запускает и закрывает приложение на каждый сценарий (около 15–30 с на штуку), печатает `PASS` или `FAIL` с выводом упавшего. Всё сразу дольше 10 минут не бывает, но запускать лучше в фоне. Не запускать, пока приложение открыто вручную.

Новая проверка в приложении — новый сценарий: первой строкой `waitfor state 120000 proj/`, дальше шаги, в конце `expect`/`waitfor`. Пункты «Проверить руками» в [todo.md](todo.md) по возможности превращать в сценарии.

## Без ручных апрувов

В `.claude/settings.json` разрешены точные формы: `.\gradlew.bat build | test | detekt | koverLog | run -PdebugCtl`, `.\scripts\debug-ctl.ps1 *`, `.\scripts\debug-scenario.ps1 [*]`. Всё остальное — апрув, поэтому:

- одна простая команда на вызов: без `cd`, `-p`, абсолютных путей, `$env:`, `&`, `;`, `|`, `2>&1`;
- не придумывать новые формы (`gradlew run` без `-PdebugCtl`, лишние флаги, `Stop-Process`) — они потребуют апрув;
- файлы читать только Read, по относительному пути внутри проекта;
- `curl` не нужен: сети у пульта нет.

## Команды

Координаты — пиксели скриншота (в dip = пиксели / `scale` из ответа `shot`). События синтетические: настоящая мышь не двигается, работать параллельно можно. Первая ошибка в списке обрывает остальные команды.

**Смотреть**

| Команда | Что делает |
|---|---|
| `state` | текст: тема; дерево (`[-]` раскрыто, `[+]` свёрнуто, `*` выделен, `@x,y` — точка клика); вкладки левой и правой половины (`*` активная, в скобках статус записи); `ui` — видимые помеченные элементы (меню, вкладки, кнопки, диалог, плашка) с центром; `messages` — сообщения приложения |
| `text [left\|right]` | полный текст активной вкладки половины |
| `log [N]` | последние N строк (30) лога приложения; файл — `build/debug-ctl/app.log` |
| `shot [имя] [x y ширина высота]` | PNG окна; с четырьмя числами — вырезка области |

**Проверять и ждать** (источники: `state`, `text`, `text-right`, `log`; `not` — наоборот)

| Команда | Что делает |
|---|---|
| `expect [not] источник подстрока` | проверка сейчас; при провале в ошибке видно текущее содержимое |
| `waitfor [not] источник мс подстрока` | ждать до `мс`, опрос каждые 50 мс. Вместо `wait` с угаданной паузой |
| `expect [not] exists путь` | есть ли файл на диске (путь от корня проекта): проверка move, rename, delete |
| `mark имя`, `expect moved имя dx dy допуск` | запомнить центр помеченного элемента и проверить сдвиг от запомненного (допуск в пикселях) |
| `expect [not] inside A in B`, `waitfor [not] inside мс A in B` | помеченный элемент A целиком в границах помеченного B (например, `tab:pic.png in tabs:left`: вкладка видна на панели). Элемента нет в композиции (вне экрана) — тоже «не внутри». Границы меток не обрезаются родителем, иначе вкладка за краем панели считалась бы целой |
| `expect [not] apart A and B` | помеченные элементы не пересекаются (путь файла и статус внизу: `bottom-path:left and bottom-status:left`) |

**Действовать**

| Команда | Что делает |
|---|---|
| `node [right] [double] имя` | клик по узлу дерева; имя как в `state`, для одинаковых — путь от корня: `fold/a.txt` |
| `arrow имя` | раскрыть или свернуть папку |
| `tap [right] [double] имя` | клик по элементу из раздела `ui`: `menu:Rename`, `button:Ok`, `dialog:Rename`, `tab:main.asm`, `tab-close:main.asm`, `banner:Keep mine`, `tree:collapseAll`, `theme-toggle`. Имя — точное или часть; не однозначно — ошибка со списком видимых. `tap tab:main.asm within tabs:left` — по видимой части вкладки, обрезанной краем панели (центр самой вкладки может лежать за краем) |
| `hover имя` | навести мышь на помеченный элемент (подсказка пути внизу — метка `tooltip`); убрать — `move 5 5` |
| `drag A -> B` | перетаскивание по именам. `A`, `B` — `node имя` (узел дерева), `tap имя` (метка: `half:left`, `half:right`, `half-empty:left`, `split:…`) или `x y`. Тащится **выделенное**: перед `drag node …` выделить узел (`node имя`) |
| `dragby A dx dy` | сдвинуть на `dx dy` пикселей: разделители панелей (`dragby tap split:tree-editor 80 0`). Сдвиг получается точным |
| `click x y [left\|right\|middle] [число]`, `move x y`, `drag x1 y1 x2 y2`, `scroll x y шаги` | мышь по координатам; `scroll` > 0 — вниз |
| `type текст` | ввод символов (кириллица тоже) |
| `key ctrl+shift+s` | сочетание: `ctrl`, `shift`, `alt`, `meta` + клавиша (`enter`, `esc`, `backspace`, `delete`, `down`, `f6`, `a`…) |
| `ext write путь \| текст` | правка «снаружи» (`\n` — перевод строки); ещё `ext delete путь`, `ext mkdir путь`, `ext rename старый \| новый`. Пути от корня проекта, наружу нельзя |
| `focus` | окно «получило фокус»: запускает сверку открытых файлов с диском (в песочнице фокус настоящий не приходит) |
| `wait мс`, `dump`, `close` | пауза; дерево компонентов AWT (отладка самого пульта); закрыть окно |
| `throw текст` | необработанное исключение на ui-потоке (проверка показа ошибок в `ErrorOverlay`: `waitfor state … [ERROR] IllegalStateException`) |

## Приёмы

- Сначала `state` и `expect` (дёшево и точно), скриншот — для вёрстки, цветов и всего, чего нет в `state`.
- Метки (`ui`) есть только у видимого: меню открыто — есть `menu:*`; диалога нет — нет `dialog:*`; `half:right` и `split:halves` — только когда в правой половине есть вкладки. Новую кнопку или меню для пульта — пометить `Modifier.debugTag("тип:имя")`.
- Панель вкладок помечена `tabs:left` / `tabs:right`. Вкладка, ушедшая за край, из композиции пропадает: `tap tab:…` по ней не сработает. Сначала расширить панель (`dragby tap split:tree-editor -N 0`) или прокрутить `scroll`.
- Позиции есть только у видимых узлов дерева. Нужный узел скрыт — `arrow` на папке, потом `node`.
- Двойной клик открывает файл; вкладка 300 мс в статусе `load` (debug-задержка). Не `wait 500`, а `waitfor state 3000 *main.asm (writable)`.
- Автосохранение через 2 с: набранное попадает в файл. Откатывать ввод `key backspace` нужное число раз; `shift+home` + `delete` стирает всю строку.
- Клик по пустому месту под текстом фокус редактору не даёт: кликать по самому тексту (первая строка — около `400 70` при масштабе 1.0; координаты зависят от монитора, сверяться по `shot`).
- Меню закрывает `key esc`. Системные окна (`JFileChooser`) на снимок не попадают.
- Внешние правки: `ext write …` потом `focus`, дальше `waitfor`.
- Перед правкой исходников приложение закрыть (`close`), иначе сборка упрётся в занятый jar.

## Осторожно

- Пульт без `-PdebugCtl` (переменная `AISDME_DEBUG_DIR`) работает на настоящем проекте и конфиге пользователя; без явной просьбы так не запускать.
- Раннер сценариев и `Stop-App` в нём трогают только процессы пульта (`aisdme.debug.dir`, `-PdebugCtl`), чужие запуски приложения — нет.
- Остановленное ошибкой приложение (скрипт вернул 3) — причина в `build/debug-ctl/app.log` или в `build/debug-run.err`.

## Не проверено

- Перетаскивание картинки средней кнопкой (`ImageViewer`): `drag` работает только левой.
- Перетаскивания вкладок в приложении нет: в `TabsBar` такого кода нет.
- Дерево после операции обновляется с задержкой ~200 мс (debounce watcher): сразу после move или delete узел ещё старый, ждать `waitfor`, а не `expect`.
- Linux: скрипты только для Windows. Руками: записать `build/debug-ctl/<id>.tmp`, переименовать в `<id>.cmd`, читать `<id>.out`.
